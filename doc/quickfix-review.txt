1. INTRODUCTION                                   *quickfix-review-introduction*

quickfix-review.nvim is a lightweight code review system that uses Neovim's
built-in quickfix list and signs to manage review comments. It supports
regular files as well as diff buffers from diffview.nvim, fugitive, and
similar plugins.

Features:
- Six default comment types: ISSUE, SUGGESTION, NOTE, PRAISE, QUESTION, INSIGHT
- Configurable comment types: Add your own or modify existing ones
- Comment type cycling: Fast workflow with +/- navigation
- Visual signs in the gutter for each comment type
- Multiline comment support with visual selection
- Export reviews to markdown format
- Reviews are saved to disk on every change and reloaded on startup
- Works with diff buffers (diffview, fugitive, codediff)
- Navigate between comments using quickfix commands

2. INSTALLATION                                   *quickfix-review-installation*

Requires Neovim 0.10 or later.

Using lazy.nvim: >lua
    {
      'your-username/quickfix-review.nvim',
      config = function()
        require('quickfix-review').setup()
      end,
    }
<
Using packer.nvim: >lua
    use {
      'your-username/quickfix-review.nvim',
      config = function()
        require('quickfix-review').setup()
      end,
    }
<
Manual installation:
Clone the repository to your Neovim packages directory and call setup().

3. CONFIGURATION                                 *quickfix-review-configuration*

Call `require('quickfix-review').setup(opts)` with a table of options. All
options are optional; defaults are shown below.

>lua
    require('quickfix-review').setup({
      -- Per-project storage directory: nil (default), a string, or
      -- function(root) -> string. See |quickfix-review-storage|.
      storage_dir = nil,

      -- Rotate the review log past this many bytes, and delete rotated
      -- logs older than this many days (nil = keep them). See
      -- |quickfix-review-rotation|.
      log_max_bytes = 5 * 1024 * 1024,
      log_retention_days = nil,

      -- Default export filename (nil = clipboard only)
      export_file = nil,

      -- Deprecated, does nothing: comments follow the file when it
      -- changes on disk (see |quickfix-review-outdated|). Setting it to
      -- true shows a one-time notice.
      prompt_on_file_change = false,

      -- Show the comment float when :cnext/:cprev/:cc/:cfirst/:clast
      -- lands on an entry of the review quickfix list
      auto_show = true,

      -- Comment types: replaces defaults if provided (see comment_types section)
      -- comment_types = { ... },

      -- Additional comment types: merged with defaults
      -- additional_comment_types = { ... },

      -- Signs (see |quickfix-review-signs|)
      -- signs = { ... },

      -- Markdown export (see |quickfix-review-export|)
      export = {
        header = '# Code Review\n\n',
        -- type_legend: generated from comment_types unless set
        item_format = '%d. **[%s]** `%s` - %s',
      },

      -- Keymaps (set one to false to disable it, or keymaps = false for none)
      -- Default type keymaps: add_issue <leader>ci, add_suggestion <leader>cs,
      --   add_note <leader>cn, add_praise <leader>cp, add_question <leader>cq,
      --   add_insight <leader>ck
      keymaps = {
        -- Comment type cycling
        add_comment_cycle = '<leader>ca',  -- Add comment with current cycle type
        cycle_next = '+',                  -- Cycle to next type
        cycle_previous = '-',              -- Cycle to previous type

        delete_comment = '<leader>cd',
        view = '<leader>cv',
        edit = '<leader>cm',
        export = '<leader>ce',
        clear = '<leader>cc',
        summary = '<leader>cS',
        save = '<leader>cw',
        load = '<leader>cr',
        open_list = '<leader>co',
        next_comment = ']r',
        prev_comment = '[r',
        goto_real_file = '<leader>cg',
        reanchor = false,  -- |:ReviewReanchor|, not mapped by default
      },
    })
<
                                                      *quickfix-review-storage*
Storage:~

Each project has its own review, kept as an append-only event log,
`log.jsonl`, inside the project's storage directory. By default that is: >
    stdpath('data')/quickfix-review/<basename(root)>-<sha256(root)[1..12]>/
<
where the last part is the first 12 hex characters of the SHA-256 of the
project root, e.g. `~/.local/share/nvim/quickfix-review/my-app-3f9a1c0b7d2e/`.

                                                      *quickfix-review-log*
The log holds one JSON object per line. The first line is a header; every
later line is an event (`add`, `delete`, `clear`, `restore`, `import`, ...)
and the review is those events replayed in order. Lines are only ever
appended, each change in a single write under a lock (a `lock` directory
next to the log), so several Neovims can share a review and no change can
overwrite another. Deleted and cleared comments stay in the log. A line
that can't be read is skipped with a warning naming its line number.

`state.json` next to the log is a cache of the replay, written on exit and
every 50 events. It is never needed: delete it and it is rebuilt from the
log.

                                                  *quickfix-review-rotation*
Once the log grows past `log_max_bytes` (default 5 MB), the change that
grew it rotates it: the log is replayed, a new `log.jsonl` starts with a
header and one `checkpoint` event holding the whole review (live comments
and the trash), and the old log is kept as `log.<unix ms>.jsonl`
(`<storage_file>.log.<unix ms>.jsonl` with `storage_file`). |:ReviewHistory|
reads the rotated logs too. They are kept forever unless
`log_retention_days` is set: then rotated logs older than that (by the time
in their name) are deleted when the review is first read in a session.
Deleted comments stay restorable, as the trash is in the checkpoint. Only
rotated logs are ever deleted. A version of this plugin from before
rotation can't read a rotated log's checkpoint and shows the review empty.
Logs are written in format v2; from this version on, a log written by a
newer version of the plugin is refused with an ERROR and left unmodified,
rather than shown empty. A log is rotated again only once it is also more
than twice the size of the checkpoint it starts with, so a review whose
checkpoint alone exceeds `log_max_bytes` doesn't rotate on every change.

The project root is the git toplevel of Neovim's global working directory,
or that directory itself outside git, with symlinks resolved. Each git
worktree has its own toplevel, so each worktree has its own review. After
|:cd| into another project (or a change by 'autochdir') the review is
re-read from that project's directory; the quickfix view and signs follow.
If that review can't be read, the list is emptied and the review is not
modified until it is fixed. |:lcd| and |:tcd| don't switch projects. The root is looked up once per directory per session, so
`git init` in an open directory takes effect after a restart. Only a
definite answer from git is kept: if `git rev-parse` fails or times out,
you get a warning, the last root git gave for that directory (else the
directory itself) is used meanwhile, and git is asked again a few seconds
later.

                                                  *quickfix-review-storage_dir*
`storage_dir` may be a function, called with the resolved root, returning
the directory to use, or a string, used as-is (shared by every project; its import from the
legacy global file takes every comment, not only one project's).

                                                  *quickfix-review-snapshots*
`snapshots/` in the storage directory holds copies of commented files, one
file per version, named by the SHA-256 of its content, so comments can
follow later edits. Content is stored canonically: lines joined with LF,
trailing CRs dropped, always ending in a newline, so CRLF and LF versions
of a file (or one missing its final newline) share a snapshot. A snapshot
whose content no longer matches its name is ignored with a warning. Files
in an encoding other than UTF-8 may give noisy results. With
|quickfix-review-storage_file| the directory is `<storage_file>.snapshots`.

A snapshot no longer named by the review's event logs (the current log and
the rotated ones kept, so also by no comment or trash entry) is deleted
once it has gone untouched for 24 hours. This runs in the background 5
seconds after startup (for the review of the current directory) and after
a log rotation. A log that can't be read, or was written by a newer
version, stops it.

                                                  *quickfix-review-outdated*
                                                     *QuickfixReviewOutdated*
When the code changes:~

Each comment is anchored to the snapshot of its file it was written
against. When the file changes, the snapshot is diffed against the file as
it is now and the comment moves with its lines: when the file is read or
reloaded after changing on disk (|BufReadPost|, |FileChangedShellPost|), as
you edit it (tracking extmarks follow the lines), and, for a file that is
not open, when it is read for the quickfix list, export or a jump (cached by
the file's size and modification time). Positions are kept in memory until
the file is saved: on |BufWritePost| every comment in it that is current or
shifted is re-anchored to the saved content (its anchor rewritten, one
`update` event per comment whose anchor changed), so it reopens where it is
now. Unsaved edits (|:q!|, |:e!|) never change a stored anchor, outdated
comments keep theirs, and writing part of a buffer or to another file
changes nothing. Diff buffers (fugitive, diffview, codediff) hold an old
revision and never move a comment.

A comment is outdated when one of its lines was changed or deleted, a line
was inserted inside its range, or its file or snapshot is missing. It stays
where its code was (a deleted range collapses to the line before it). Lines
added or removed next to a range, CRLF line endings and a missing final
newline don't make it outdated. An outdated comment is shown with:
- the `QuickfixReviewOutdated` sign highlight, linked to `DiagnosticWarn`
  unless you define it
- `[outdated] ` in front of its quickfix row
- "outdated — code changed since comment" at the top of its float
- ` (outdated)` after its location in the export

While a file is open, a comment whose whole range is deleted becomes
outdated at once; other in-session edits inside a range are checked when
the file is saved or next read from disk. Comments made before snapshots
existed stay at their saved line and are never outdated; saving their file
gives them a snapshot. Use |:ReviewReanchor| to accept an outdated
comment's new position.

                                                 *quickfix-review-migration*
Earlier versions kept the review in `comments.json` in the same directory.
When a project has a `comments.json` but no log yet, its comments are
copied into a new log as one `import` event and the file is renamed to
`comments.json.pre-log.bak`, byte for byte as it was. From then on the log
is the review: a `comments.json` that reappears next to it (written by an
older version or another tool) is not read; you get one warning and the
file is left alone.

Older versions still kept every project's comments in one global file,
`stdpath('data')/quickfix-review.json`. The first time a project with
neither a log nor a `comments.json` is opened, the comments in that file
whose path is inside the project are imported ("imported N comments from
..."). The global file is only read, never changed. If it is missing but
`quickfix-review.json.pre-log.bak` exists (left by an older version used
with `storage_file` pointing at the global file), that copy is read
instead. The import happens
once per project: once its log exists, even with nothing imported, nothing
is imported again.

                                                 *quickfix-review-storage_file*
`storage_file` is deprecated. When set, one review is used for every
project, as before: no storage directory, no switching on |:cd|, and no
import from the global file. Its log and cache sit next to the path given:
`<storage_file>.log.jsonl` and `<storage_file>.state.json` (and a
`<storage_file>.lock` directory while writing). An existing file at that
path is migrated to the log and renamed to `<storage_file>.pre-log.bak`,
except the global file `stdpath('data')/quickfix-review.json` itself: it is
left in place, so per-project reviews can still import from it once
`storage_file` is removed. If you copied the old full configuration example, remove its
`storage_file` line to get per-project reviews.

                                                *quickfix-review-comment-types*
Custom comment types:~

To add types while keeping defaults, use `additional_comment_types`: >lua
    require('quickfix-review').setup({
      additional_comment_types = {
        security = { sign = '🔒', highlight = 'DiagnosticError', description = 'Security concern' },
        perf = { sign = '⚡', highlight = 'DiagnosticWarn', description = 'Performance issue' },
      },
      keymaps = {
        add_security = '<leader>cx',
        add_perf = '<leader>cf',
      },
    })
<
To replace defaults entirely, use `comment_types`: >lua
    require('quickfix-review').setup({
      comment_types = {
        bug = { sign = '🐛', highlight = 'DiagnosticError', description = 'Bug' },
        idea = { sign = '💡', highlight = 'DiagnosticInfo', description = 'Idea' },
      },
      keymaps = {
        add_bug = '<leader>cb',
        add_idea = '<leader>ci',
      },
    })
<
Signs and continuation signs are auto-generated from comment_types.
Keymaps follow the pattern `add_<type>` (e.g., `add_bug`, `add_idea`).

`comment_types` must be a non-empty table; anything else is ignored with a
warning and the default types are used.

Types are listed (when cycling, in the summary and in the export legend) in
the default order issue, suggestion, note, praise, question, insight, then
any other types sorted by name.

                                                        *quickfix-review-signs*
Signs:~

`signs` maps each type name, and `<type>_continuation` (the sign on the
middle lines of a range), to `{ text = ..., texthl = ... }`. It is generated
from comment_types (`sign` and `highlight`, with `│` as the continuation
text). A non-empty `signs` table replaces the generated one entirely: >lua
    require('quickfix-review').setup({
      signs = {
        issue = { text = '!', texthl = 'DiagnosticError' },
        issue_continuation = { text = '|', texthl = 'DiagnosticError' },
        -- ... one pair per comment type
      },
    })
<
                                                       *quickfix-review-export*
Export format:~

`export.header`       Text at the top of the export.
                      Default: `'# Code Review\n\n'`
`export.type_legend`  Text after the header. Generated from comment_types
                      (`Comment types: ISSUE (Problems to fix), ...`) unless
                      set; set it to `''` to leave it out.
`export.item_format`  A |string.format()| pattern for each comment, given
                      four values in this order: the index (a number), the
                      TYPE, the location (`file:line` or `file:start-end`)
                      and the comment text.
                      Default (as in the setup example above), which
                      gives lines like: >
                          1. **[ISSUE]** `src/main.lua:12` - Fix this
<                     A pattern that does not accept these values falls
                      back to the default with a warning.

                                                *quickfix-review-disable-keymaps*
To disable specific keymaps, set them to `false`: >lua
    require('quickfix-review').setup({
      keymaps = {
        add_praise = false,  -- Disable this keymap
      },
    })
<
To disable every keymap the plugin makes, set `keymaps = false`. Commands
still work. Calling setup() again removes maps that are no longer
configured.

4. USAGE                                                 *quickfix-review-usage*

Basic workflow:

1. Open the file(s) you want to review
2. Navigate to a line and press `<leader>ci` to add an ISSUE comment
   (or use other comment type keymaps)
3. Enter your comment text when prompted
4. Repeat for all comments
5. Press `<leader>co` to open the quickfix list and see all comments
6. Press `<leader>ce` to export the review to markdown

Comment type cycling:~

For faster workflow, use the cycling feature:
1. Press `+` to cycle through comment types (or `-` to go backwards)
2. Press `<leader>ca` to add a comment with the current type

The current comment type is shown in the status message.

Multiline comments:~

Select lines in visual mode, then press any add comment keymap to create
a comment spanning multiple lines. Signs will mark the start and end lines
with continuation signs on middle lines.

Working with diff buffers:~

When reviewing in diffview or fugitive diff buffers, comments are
automatically associated with the real file path. You can use
`<leader>cg` to jump from a diff buffer to the actual file. A diff buffer
shows a comment's signs at its original lines only when it holds exactly
the revision the comment was written against; otherwise it shows none.
Saving the working file re-anchors the comment to the saved content, so
after that a buffer holding the older revision no longer shows it.

Navigating comments:~

Use `]r` and `[r` to jump between review comments across all files.

Where comments live:~

The plugin keeps comments itself, not in the quickfix list, and writes
every change to the project's event log (see |quickfix-review-log|)
immediately. The review is read back at setup, and events appended by
another Neovim (or an external script) are picked up as they appear, so it
is never lost when you quit.

The quickfix list is only a view: `<leader>co` and |:ReviewLoad| publish
the review as a new quickfix list, which then follows changes to the
review. Replacing the quickfix list (LSP references, |:grep|) doesn't
touch the review, and `:cnext`/`:cprev` work as usual on the view.
Landing on a review entry with `:cnext`, `:cprev`, `:cc`, `:cfirst` or
`:clast` shows its comment float (set `auto_show = false` to turn this off).
Other quickfix lists, and the |:ReviewTrash| list, never show it.

Deleting comments:~

Use `<leader>cd` to delete comments at the current line. In visual mode,
all comments in the selected range will be deleted. In the quickfix window,
press `dd` to delete the comment under cursor.

5. COMMANDS                                           *quickfix-review-commands*

                                                              *:ReviewAdd*
:[range]ReviewAdd {type}
                        Add a comment of {type} at the current line, or
                        over [range]. <Tab> completes the configured types.

                                                          *:ReviewAddIssue*
:[range]ReviewAddIssue  Add an ISSUE comment at the current line, or over
                        [range]. Issues indicate problems that must be fixed.

                                                     *:ReviewAddSuggestion*
:[range]ReviewAddSuggestion
                        Add a SUGGESTION comment. Suggestions are
                        improvements to consider.

                                                           *:ReviewAddNote*
:[range]ReviewAddNote   Add a NOTE comment. Notes are observations or
                        explanations.

                                                         *:ReviewAddPraise*
:[range]ReviewAddPraise Add a PRAISE comment. Praise highlights good code or
                        practices.

                                                       *:ReviewAddQuestion*
:[range]ReviewAddQuestion
                        Add a QUESTION comment.

                                                        *:ReviewAddInsight*
:[range]ReviewAddInsight
                        Add an INSIGHT comment.

                                                         *:ReviewAdd<Type>*
:[range]ReviewAdd<Type> setup() makes one such command for every configured
                        comment type, custom ones included, CamelCased from
                        the type name: `nit` gives `:ReviewAddNit`,
                        `needs_work` gives `:ReviewAddNeedsWork`. Type
                        names are lowercased at setup (with a warning), so
                        `Bug` becomes `bug`. Only names of lowercase
                        letters, digits and `_` get a command; any other
                        name (such as `needs-work`) warns and is reachable
                        through |:ReviewAdd|. A type left out of the configuration
                        (e.g. when `comment_types` replaces the defaults)
                        loses its command.

                                                           *:ReviewDelete*
:[range]ReviewDelete    Delete comment(s) at the current line, or every
                        comment overlapping [range].

                                                             *:ReviewView*
:ReviewView             View comment at the current line.

                                                             *:ReviewEdit*
:ReviewEdit             Edit the text of the comment at the current line,
                        with the input prefilled with its current text.
                        If several comments cover the line, you pick one
                        first. In the review's quickfix window, edits the
                        comment on the row under the cursor. Its id, kind
                        and position are unchanged. Comment text is a
                        single line. Cancelling (or an empty input)
                        changes nothing. The edit is logged as one
                        `update` event, shown by |:ReviewHistory| with the
                        old and new text; it is not undone by
                        |:ReviewRestore|.

                                                           *:ReviewExport*
:ReviewExport           Export all comments to markdown format.
                        Copies to clipboard and optionally writes to file.

                                                            *:ReviewClear*
:ReviewClear[!]         Clear all review comments and signs. Asks for
                        confirmation first (default No); with ! it does not.
                        Cleared comments can be brought back with
                        |:ReviewRestore|.

                                                            *:ReviewTrash*
:ReviewTrash            List the deleted and cleared comments, newest
                        first, in a quickfix list of its own titled
                        "Review trash" (the review's list is left alone).
                        Each row shows when and how (delete or clear) the
                        comment was removed, its kind, the first line of
                        its body and its id.

                                                          *:ReviewRestore*
:ReviewRestore [id]     Restore the deleted comment {id}, with the same id
                        and content (completes over the ids in the trash).
                        Without an id, restore the most recently deleted
                        comment, or, if the last removal was a
                        |:ReviewClear|, every comment it cleared (asking
                        first, default No, when that is more than one).
                        Restoring a comment that is already in the review
                        only says so. A restore is appended to the log
                        like any other change.

                                                          *:ReviewHistory*
:ReviewHistory [id]     Show the logged events of comment {id} in order
                        (completes over live and deleted ids), or, without
                        an id, the last 50 events of the review: time,
                        op, kind, file:line, and for an update the fields
                        it changed.

                                                         *:ReviewReanchor*
:ReviewReanchor         Accept where the outdated comment at the cursor is
                        now: re-anchor it to the buffer's lines as they are
                        (unsaved edits included, as when adding a comment),
                        so it is current again. Every outdated comment
                        covering the cursor line is re-anchored, one
                        `update` event each. On a line with no outdated
                        comment it only says so. Must be run from the file
                        itself, not a diff buffer. Not mapped by default;
                        set `keymaps.reanchor` to map it.

                                                             *:ReviewSave*
:ReviewSave             Write the review's `state.json` cache. Every
                        change is already in the log as it is made, so
                        this is rarely needed (see |quickfix-review-log|).

                                                             *:ReviewLoad*
:ReviewLoad             Replay the review's log from disk and show it in
                        the quickfix list.

                                                          *:ReviewSummary*
:ReviewSummary          Show a summary of comment counts by type.

                                                             *:ReviewGoto*
:ReviewGoto             Jump from a diff buffer to the real file.

6. KEYMAPS                                             *quickfix-review-keymaps*

Default keymaps (normal and visual mode where applicable):

  Keymap          Description~
  --------------- ----------------------------------------
  `<leader>ci`    Add ISSUE comment
  `<leader>cs`    Add SUGGESTION comment
  `<leader>cn`    Add NOTE comment
  `<leader>cp`    Add PRAISE comment
  `<leader>cq`    Add QUESTION comment
  `<leader>ck`    Add INSIGHT comment
  `<leader>ca`    Add comment with current cycle type
  `+`             Cycle to next comment type
  `-`             Cycle to previous comment type
  `<leader>cd`    Delete comment at cursor/selection
  `<leader>cv`    View comment at cursor
  `<leader>cm`    Edit comment at cursor
  `<leader>ce`    Export review to markdown
  `<leader>cc`    Clear all comments
  `<leader>cS`    Show review summary
  `<leader>cw`    Write review to disk
  `<leader>cr`    Re-read review and show it in quickfix
  `<leader>co`    Show review in quickfix and open the window
  `]r`            Next review comment
  `[r`            Previous review comment
  `<leader>cg`    Go to real file from diff

`keymaps.reanchor` (|:ReviewReanchor|) is not mapped by default.

Quickfix window keymaps:
  `dd`            Delete comment under cursor
  `<leader>cd`    Delete comment under cursor (the global
                  `keymaps.delete_comment`; `false` leaves only `dd`)
  `<leader>cm`    Edit comment under cursor (the global `keymaps.edit`)

All keymaps can be customized or disabled via configuration.

7. FUNCTIONS                                         *quickfix-review-functions*

The following functions are available in the `quickfix-review` module:

require('quickfix-review').setup({opts})               *quickfix-review.setup()*
    Initialize the plugin with optional configuration.

require('quickfix-review').add_comment({type}, {range})
                                                  *quickfix-review.add_comment()*
    Add a comment of the given type at the current line or range.
    Type should be 'ISSUE', 'SUGGESTION', 'NOTE', 'PRAISE', 'QUESTION',
    'INSIGHT', or any custom type. Range is optional {start_line, end_line}.

require('quickfix-review').add_comment_visual({type})
                                           *quickfix-review.add_comment_visual()*
    Add a comment for the visual selection.

require('quickfix-review').cycle_next_comment_type()
                                       *quickfix-review.cycle_next_comment_type()*
    Cycle to the next comment type.

require('quickfix-review').cycle_previous_comment_type()
                                   *quickfix-review.cycle_previous_comment_type()*
    Cycle to the previous comment type.

require('quickfix-review').add_comment_cycle()
                                             *quickfix-review.add_comment_cycle()*
    Add a comment using the current cycle type.

require('quickfix-review').delete_comment({range})
                                               *quickfix-review.delete_comment()*
    Delete comments at the current line or range.

require('quickfix-review').view_comment()           *quickfix-review.view_comment()*
    View the comment at the current line.

require('quickfix-review').edit_comment()           *quickfix-review.edit_comment()*
    Edit the text of the comment at the current line, or of the row under
    the cursor in the review's quickfix window. See |:ReviewEdit|.

require('quickfix-review').export_review()         *quickfix-review.export_review()*
    Export all comments to markdown and clipboard.

require('quickfix-review').clear_review({opts})     *quickfix-review.clear_review()*
    Clear all comments and signs. With `{ confirm = true }` ask first
    (default No); without it, clear at once.

require('quickfix-review').save_review()             *quickfix-review.save_review()*
    Write the review's `state.json` cache (every change is already in
    the log).

require('quickfix-review').load_review()             *quickfix-review.load_review()*
    Replay the review's log from disk and show it in the quickfix list.

require('quickfix-review').comments()                 *quickfix-review.comments()*
    All review comments, in creation order. Treat as read-only. Each is a
    record `{ id, filename, kind, body, response, lnum, end_lnum, context,
    anchor, pos, created_at }`: `kind` is the lowercase comment type, `body`
    the text without any `[KIND]` prefix, and `response` and `context` (the
    captured commit and snippet) may be nil. `anchor` is
    `{ sha, lnum, end_lnum, lines, before, after }`, written when the
    comment was made and rewritten when its file is saved while it is
    current or shifted, or by |:ReviewReanchor|: `sha` names a snapshot of the commented buffer (as the
    reviewer saw it, unsaved edits included) that `lnum`/`end_lnum` refer
    to, `lines` the commented lines (at most 50) and `before`/`after` up to
    2 lines either side. Comments from older versions, or whose snapshot
    could not be saved, have no `sha` (older ones also no `lines`). `pos`
    is `{ sha, lnum, end_lnum, state }`, where the comment is displayed;
    it is derived, never saved. A record may also carry `extra`: a
    table of fields from stored records that the plugin does not know
    (written by other tools), preserved and logged at the top level of the
    record.

require('quickfix-review').summary()                   *quickfix-review.summary()*
    Print a summary of comment counts.

require('quickfix-review').summary_data()         *quickfix-review.summary_data()*
    The summary as data: `{ total = n, by_type = { { name, count }, ... } }`,
    with one entry for every configured comment type (lowercase name), in
    the order described in |quickfix-review-comment-types|.

require('quickfix-review').open_list()               *quickfix-review.open_list()*
    Show the review in the quickfix list and open the quickfix window.

require('quickfix-review').jump_comment({direction})
                                                 *quickfix-review.jump_comment()*
    Jump to the next ({direction} 1) or previous ({direction} -1) comment
    across all files, ordered by file then line and wrapping around at the
    ends, and show it. A comment past the end of its file lands on the last
    line.

require('quickfix-review').goto_real_file()       *quickfix-review.goto_real_file()*
    Jump from a diff buffer to the actual file.
